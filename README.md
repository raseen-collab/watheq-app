# وثيق — منصة سحابية بحسابات (Next.js + Supabase + Vercel)

## ما فيه المشروع
- تسجيل دخول/إنشاء حساب.
- لوحة تحكم بوضعين (جمعيات ملاك + إدارة أملاك) — بنفس هوية وثيق.
- بيانات كل مستخدم منفصلة تمامًا (Row Level Security على Supabase).
- كل ما في اللوحة القديمة يعمل هنا: إضافة/تعديل/حذف، تنبيه الشهادة، تذكير واتساب، توليد إنذار نظامي.

---

## ما فعلتُه أنا ✅
- بنيت المشروع كاملًا (Next.js 14 + TypeScript + Tailwind).
- كتبت مخطط قاعدة البيانات مع سياسات الأمان.
- عملاء Supabase (متصفح/خادم) + Middleware حماية اللوحة.
- صفحة الدخول، اللوحة بوضعيها، الإنذارات النظامية، إجراءات واتساب.

## ما تفعله أنت (بالترتيب) 👇

### الخطوة 1 — Supabase (5 دقائق)
1. اذهب لـ https://supabase.com وسجّل بحساب GitHub.
2. اضغط **New project**. اختر منطقة قريبة (Frankfurt أنسب للسعودية).
3. **حدّد كلمة مرور قاعدة بيانات قوية واحفظها** (لن تحتاجها الآن، لكن احفظها).
4. انتظر ~2 دقيقة حتى ينشأ المشروع.
5. من القائمة اليسرى: **SQL Editor** → **New query** → افتح ملف `supabase/schema.sql` من هذا المشروع، انسخ كل محتواه، الصقه، واضغط **Run**. المفروض تظهر: "Success. No rows returned".
6. من القائمة اليسرى: **Project Settings** (رمز الترس) → **API**. ستجد قيمتين مهمتين:
   - **Project URL** (يبدأ بـ https://).
   - **anon public key** (طويل، ينتهي بـ anon key).
   احفظهما — ستضعهما في Vercel.

### الخطوة 2 — رفع المشروع لـ GitHub (5 دقائق)
1. أنشئ مستودعًا جديدًا فارغًا على GitHub اسمه مثلًا `watheq-app` (**غير** المستودع القديم — هذا مشروع مختلف).
2. حمّل ملفات هذا المجلد (`watheq-app` كاملًا).
3. ارفع كل الملفات إلى المستودع (Add file → Upload files → اسحب كل الملفات مرة واحدة).
   > **مهم:** لا ترفع مجلد `node_modules` (إن ظهر لك، تجاهله).
4. Commit changes.

### الخطوة 3 — Vercel (5 دقائق)
1. اذهب لـ https://vercel.com وسجّل بـ GitHub.
2. **Add New → Project** → اختر مستودع `watheq-app`.
3. Framework Preset يجب أن يكون **Next.js** (يكتشفه تلقائيًّا).
4. **قبل Deploy** — افتح **Environment Variables** وأضف اثنين:
   - `NEXT_PUBLIC_SUPABASE_URL` = Project URL من Supabase.
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = anon key من Supabase.
5. اضغط **Deploy**. انتظر 2-3 دقائق.
6. سيعطيك رابطًا مثل `watheq-app-xxx.vercel.app` — هذا موقعك الحيّ.

### الخطوة 4 — التجربة (دقيقتان)
1. افتح الرابط.
2. سيحوّلك لـ `/login`. أنشئ حسابًا جديدًا.
3. تحقق من بريدك (قد يذهب لـ Spam)، فعّل الحساب.
4. سجّل الدخول → ستفتح اللوحة.
5. جرّب إنشاء جمعية، إضافة ملّاك، تسجيل دفعة. البيانات تُحفظ في Supabase وترجع كما هي عند أي دخول.

## بعد النشر: ماذا نفعل مع الموقع الحالي؟
الموقع التسويقي الحالي (`watheqapp.netlify.app`) يبقى كما هو. عدّل فيه رابط "لوحة التحكم" ليشير للتطبيق الجديد على Vercel. لن نلمس المستودع القديم.

## استكشاف الأخطاء
- **"Invalid API key"** في Vercel → تأكد من نسخ المتغيرين بدون فراغات.
- **الدخول لا يعمل** → في Supabase → Authentication → Providers → تأكّد أن Email مفعّل.
- **بريد التفعيل لا يصل** → في Supabase → Authentication → Email Templates، يمكن إيقاف التحقّق للاختبار.
- **البيانات لا تظهر** → في Supabase → Table Editor → افتح جدولًا وشاهد الصفوف. إن ظهرت فالكتابة ناجحة والقراءة عبر RLS.
